# 杭州麻将何切训练器 - 设计文档

## 概述

微信小程序形态的杭州麻将何切训练器。面向已会打牌但想提升牌技的玩家，通过实时牌效分析帮助用户理解最优打牌决策。

## 核心功能

随机生成手牌 → 用户选择打哪张 → 系统实时计算所有选择的牌效率 → 对比展示最优解与用户选择 → 解析原因

所有计算在小程序端完成，无需服务器。

## 杭州麻将规则要点

### 牌面
- 136张牌（万筒条各36张、风牌16张、箭牌12张），不使用花牌
- 白板(4张)为财神（百搭），可替代任意牌

### 胡牌
- 基本条件：4组面子（顺子/刻子）+ 1对将
- 特殊牌型：七对子
- 默认只能自摸胡牌；三连庄后庄闲之间可放冲
- 可以吃（上家）、碰、杠

### 特色规则
- **爆头**：手中1张财神做单牌 + 四组完整面子，摸任意牌可胡，2倍
- **财飘**：爆头状态下用财神胡牌，4倍
- **杠开**：杠后自摸，2倍
- **杠爆**：杠后爆头，4倍
- **杠飘**：杠后财飘，8倍
- **三摊承包**：对同一玩家吃碰杠满3次，该玩家承担所有赔偿
- **漏胡/漏碰**：放弃胡/碰后，本圈不能再胡/碰同张牌
- 番种之间为乘法叠加

### 七对系列
- 七对(2倍) → 豪华七对(4倍) → 两豪华(8倍) → 三豪华(16倍)


## 核心算法

### 向听数计算

向听数 = 距离胡牌还差几步（0=听牌，-1=已胡）。

算法：
1. 普通胡牌路线：4面子+1将
   - 向听数 = 8 - 2×面子数 - 搭子数
2. 七对路线：7对子
   - 向听数 = 6 - 对子数
3. 爆头路线：1财神单牌+4完整面子
   - 需特殊处理
4. 取三条路线的最小向听数
5. 财神处理：每张财神可减少1向听

### 有效进张分析

对手牌中每张可打的牌，计算：
1. 打掉后的向听数
2. 打掉后的有效进张数（能让向听数减少的牌及其剩余张数）
3. 综合评分 = 向听数优先，同向听数比有效进张数

### 发牌器（难度控制）

- **入门**：听牌或一向听的好牌型，无财神，最优解明显
- **进阶**：一向听至二向听，含1-2张财神
- **高级**：需要多路线判断，含财神+七对/爆头可能

通过「生成→检测→过滤」确保题目质量：
- 至少有2个选择的牌效差距 > 2张进张
- 避免所有选择效果相同的无意义题目

## 页面设计

### 4个页面
1. **首页**：开始练习、难度选择、历史统计概览
2. **练习页**：展示13张手牌，用户点击选择打出的牌
3. **结果页**：展示用户选择 vs 最优选择的牌效对比、文字解析
4. **统计页**：总题数、正确率、各难度表现、常见错误类型

### 交互
- 牌面点击高亮，再次点击确认打出
- 结果页牌效对比按进张数降序排列，最优解高亮
- 解析文字简洁，说清"为什么"

## 技术架构

```
微信小程序（纯前端，无服务器）
├── pages/
│   ├── index/        - 首页
│   ├── practice/     - 练习页
│   ├── result/       - 结果页
│   └── stats/        - 统计页
├── components/
│   ├── tile/         - 麻将牌组件
│   ├── hand/         - 手牌展示组件
│   └── analysis/     - 牌效分析展示组件
├── core/
│   ├── tiles.js      - 牌面定义与工具函数
│   ├── hand-eval.js  - 向听数计算 + 有效进张分析
│   ├── hu-check.js   - 胡牌判定（含财神百搭）
│   ├── dealer.js     - 发牌器（难度控制）
│   └── analyzer.js   - 牌效分析器（生成解析文字）
└── utils/
    └── storage.js    - 本地存储（练习记录）
```

## MVP范围

### 包含
- 随机发牌（3个难度）
- 向听数计算（含财神）
- 有效进张分析
- 牌效对比展示

- 本地练习记录
